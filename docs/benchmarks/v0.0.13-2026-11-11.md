# RayoPDF 0.0.13 on the harness, 2026-11-11

0.0.13 is round 5: output quality on scientific papers, measured on a new development split of
READoc ([baselines-readoc-dev](baselines-readoc-dev-2026-11-10.md)), and more of a document's work
on its threads (method and steps: [performance.md](../development/performance.md#fifth-round-a-documents-work-on-its-threads-2026-11-10)).
Same machine and harness as [the baselines](baselines-2026-11-05.md); core alone unless the
bundle (core with the OCR add-on beside it) is named. The READoc suite (`readoc`) and the
weasyprint producer are holdouts: their numbers below were measured once, on this version, and
never inspected per document.

What changed in the output, each rule general and tested, each step landed through a gate that
re-scores every development suite:

- **Headings:** the title above the sections of a bookmark tree that starts at them; small
  capitals in headings written in the source's case; bookmarks matched across numbering, hyphens
  and contents lines; standard unnumbered sections (Abstract, References, Acknowledgments,
  Appendix) alone on a line, and an abstract's label run in with a dash or colon.
- **Tables:** TeX rules that dvips and Ghostscript paint as one-sample stencil masks; listing
  line numbers as list markers (algorithm boxes are no tables); label bands and smaller-type
  sub-lines in rule stacks; figure regions (text inside a figure is no table); lattice boundaries
  that avoid header labels; empty lattice rows dropped; two numbered lines in one ruled row as two
  rows.
- **Text:** Type 3 pixel fonts at their real size; equation numbers as their own paragraphs;
  double-spaced paragraphs joined; a paragraph rejoined around the floats that split it; figure
  text marked; affiliations in the title block kept as text.

`build/static/rayopdf`: GCC 13.3, `-O2`, static-pie.

  below pymupdf and docling. Two causes left are measured: READoc's table metric reads pipe tables
  only, and RayoPDF writes a table with spanning cells as HTML (D6); writing every table as a pipe
  table would give 0.640 on the split but put odl TEDS (0.869) under docling's and olmOCR
  `table_tests` (0.605) under the best text-layer tool's. Cells holding `%` score 0 for every tool.
- **Text on papers:** `seg_kt` 0.953 → 0.965 on the holdout. The largest cause left on the split

[performance.md](../development/performance.md#results-0012-against-round-5s-final-tree)):

| odl fresh process, ms a document (median) | 0.890 | 0.911 | ≤ 1 |
| 27 documents of 4 to 39 pages, four cores, default threads | 147.3 ms | 147.1 ms | – |
| a JPEG 2000 page with its image written | 126.0 ms | 108.8 ms | – |
| 80 JPEG 2000 documents with images written, four cores (loaded machine) | 45.3 s (images on one thread) | 19.6 s | – |

On the one-page odl documents round 5 costs 2.5 % fresh, 2.9 % of warm throughput and 6 % of
batch task-clock, and the warm p95 grew 0.699 → 0.826 ms. User instructions of
`--batch --workers=1` (perf stat, per landing) place it: odl +7.1 % over the round, of which
+2.3 % came with the figure regions (6239f1a), +6.5 % with the second table landing (81dd833)
and −1.9 % with the text landing that bounded the figure-region grid (1309b2e); SafeDocs (40
documents) +5.6 %, olmOCR `multi_column` +6.6 %, `tables` +5.8 %, `arxiv_math` +2.8 %. The speed
bar still holds; winning this back is the next round's first performance step.

## Robustness

Code 4774c53 (0.0.13 changes only VERSION and documents), 2026-11-11:

- Tests pass in the release, ASan + UBSan, ThreadSanitizer and Windows (Wine) builds, 24 each
  (new: `layout_pages` runs the shared-document mode); 0 warnings.
- Every output change landed through the quality gate (the development suites re-scored, no
  metric below its base by more than 0.003, 0.006 for olmOCR pass rates); every performance step
  through the byte gate (identical output over synthetic and odl with images off, on and structure
  off) and the workers matrix (2, 4 and 8 threads against one).
- New fuzz target `fuzz_layout_pages`: converts with several page threads and compares Markdown
  and report with one thread (1,203 s, 10,473 runs, clean; it found the nesting-limit order fixed
  in e66f40e). Changed parsers were fuzzed per step, for example `fuzz_layout_tables` 600 s
  (660 k runs) and `fuzz_layout_document` 10 min (2.6 M runs), clean.
- A campaign of an hour per target over all 24 targets runs on this code for the release check.
