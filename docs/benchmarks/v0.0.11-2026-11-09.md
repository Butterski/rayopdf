# RayoPDF 0.0.11 on the harness, 2026-11-09

0.0.11 adds optional LaTeX math, `--math=latex` (roadmap D6). Formulas found in the text layer
are written as `$…$` and `$$…$$` LaTeX rebuilt from glyph geometry: sub- and superscripts,
fractions, radicals, large operators with limits, accents, matrices and cases, aligned rows,
function names and math alphabets. An equation number follows its display as `(n)`; `\tag{n}`
scored lower with olmOCR's KaTeX renderer. TeX math fonts are recognised by name, and glyphs they
leave without Unicode are read through KaTeX's font tables (generated by `tools/gen_math_tables.py`
from KaTeX v0.16.21, MIT). Anything the reconstruction cannot place stays Unicode text, and every
formula is bounded in size, depth and work. The default output is unchanged.

Same machine and harness as [the baselines](baselines-2026-11-05.md); core alone,
`build/static/rayopdf` (3,515,432 bytes, +152,352 for the math code and tables).

- The olmOCR `arxiv_math` failures left: doubly nested scripts that line building separates,

  differ in form only (`\le` against `\leqslant`, `\mid` against `|`).

## Speed and robustness

In process, release libraries, CPU 3, odl, default mode, four alternating rounds: 0.0.10
0.414–0.420 ms/page median, 0.0.11 0.419–0.421 (+0.7 %); LaTeX mode about +31 %. The default
output is byte-identical to 0.0.10 on synthetic, odl and olmOCR (and on the scanned suite).

Core tests pass under ASan + UBSan, ThreadSanitizer, the Windows build and the OCR configuration;
the new `fuzz_layout_math` ran 5 minutes twice, clean (its clang build found a dangling string
view in the wide-accent code, fixed); full ASan sweeps of 2,802 PDFs in both math modes: 0
crashes, 0 hangs, 0 sanitizer reports.
