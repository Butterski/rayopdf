# RayoPDF 0.0.4 on the harness, 2026-11-06

What changed since [0.0.3](v0.0.3-2026-11-06.md):

- **Page furniture:** on any page, the outermost row of the top or bottom 12 % is removed when it
  is set apart from the text by more than its line spacing and reaches both text edges, carries a
  page number or is set below body size; footnote-like rows, code and bold rows with a page number
  stay. Sideways margin stamps ("Downloaded from …") are removed.
- **Reading order:** columns recognised by character weight (formulas and figure labels no
  longer disqualify a column); label columns ("[12]", line numbers) read with the text on their
  baselines; gutter-spanning lines cut the page only when at least 1.3× the median line length;
  bridging lines set aside when no clean gutter exists; Breuel's partial order where no cut
  works; images placed after the paragraph they would split.
- **Headings:** run-in headings (a bold run that starts a line, as LaTeX `\paragraph` sets them)
  split off as their own heading; table-of-contents entries, author lines, rotated margin text
  and one-letter lines are not headings; a large chapter number joins its title; table text
  counts towards the body size; bold headings from 0.915× body size.
- **Text:** "(2)" and "(iv)" enumerators kept as text; monospace-only pages written as
  paragraphs; wrapped listing lines joined to their numbered line.
- **Tables:** boxes drawn apart joined into one grid; partial horizontal rules no longer split
  rows (multi-line header cells); missing vertical rules split a row when text sits on both sides;
  striped tables joined across their shaded rows; closed rule tables allow an empty body column;
  at least 40 % of cells filled; wrapped header lines merged into one header row; whole-cell
  emphasis dropped (bold header rows are the table's styling); Unicode math letters count as math.
- **Reader:** page attributes resolved on first use, smaller Flate decode tables, `--inspect`
  written with one system call.

Same machine and harness as [the baselines](baselines-2026-11-05.md). RayoPDF ran as the harness's
`cli` tool: `build/static/rayopdf` (GCC 13.3, `-O2`, fully static, 2,087,728 bytes),
`rayopdf --convert {in} {out}` with its default image output. All numbers are reproduced here.

## Speed and memory

Fresh process: one pinned core, the 200 odl PDFs and 6 multi-page synthetic PDFs, a process per
document started from Python (about 1 ms of that is Python's).

| run | pages/s | ms/page median | ms/page p95 | cold start s | peak RSS MiB |
|---|---|---|---|---|---|
| 0.0.3, `--images=none` | 344.5 | 2.97 | 4.16 | 0.03 | 13.5 |
| 0.0.4, `--images=none` | 342.7 | 2.95 | 4.21 | 0.03 | 13.4 |
| 0.0.4, images written (default) | 154.7 | 3.31 | 15.94 | 0.03 | 188.2 |

In process (release libraries, CPU 3, the 200 odl PDFs, best of 3 per document, images off, three
alternating rounds): 0.0.3 0.851–0.861 ms/page median and 1.87–1.89 p95; 0.0.4 0.875–0.881 median
and 1.98 p95, 2–3 % slower at the median.

`--inspect`, fresh process from a native `posix_spawn` timer (CPU 3, 11 runs per file, median of
the per-file medians over odl): 0.350 ms; an empty static C program measured 0.250 ms in the same
run. The M1 gate of 0.3 ms is not met. Measured inside a fresh process: opening the file 15–18 µs
(four system calls), `Document::Open` 21–23 µs (about 5 µs when warm; the rest is first touches
of file pages), unmapping about 4 µs net; the remainder is start-up of the 2 MB binary over an
empty one (stdio, libstdc++'s emergency exception pool, more code pages).

## Robustness

- Full conversions with ASan + UBSan, images written (2,802 PDFs: synthetic, odl, olmOCR
  born-digital, SafeDocs): 0 crashes, 0 hangs, 0 sanitizer reports.
- Five-minute fuzz runs at the end of the round, each on its owner's final code:
  `fuzz_layout_tables` (52,617 runs), `fuzz_layout_content` (155,993), `fuzz_layout_document`
  (3,346), `fuzz_pdf_document` (21,485), all clean.

## Known gaps

Those of [0.0.3](v0.0.3-2026-11-06.md#known-gaps) still open, except run-in headings and wrapped
listing lines, plus:

- olmOCR `table_tests` (0.540 against 0.615): dense borderless tables, frames drawn as one shape,
  small grids beside charts.
- odl tables still low: 200 (slide grid), 116 (no drawn lines), 119, 078, 187.
- Running heads of single-page documents set as headings (6 odl documents); slide callouts.
- A level-5 run-in heading comes out as level 4 (LaTeX sets both alike).
- Headings at body size and weight have no signal (odl 107, 151).
