# RayoPDF 0.0.1 on the harness, 2026-11-05

The first converter (`rayopdf --convert`), measured with the harness of
[evaluation.md](../development/evaluation.md) against the competitors of
[baselines-2026-11-05.md](baselines-2026-11-05.md) (same machine, versions and data; olmOCR as
rescored there). RayoPDF ran as the harness's `cli` tool: `build/static/rayopdf` (GCC 13.3, `-O2`,
fully static), `rayopdf --convert {in} {out}`, one process per document. All numbers are
reproduced here; none are claimed.

- RayoPDF leads every tool, docling included, on Markdown structure: heading tree (MHS) and
  construct F1 on both tagged and untagged synthetic PDFs, with list items, links, emphasis and
  block quotes the largest gains.
- It trails on raw text similarity: NID is 0.005 to 0.041 below the best text-layer tool on every
  synthetic producer and 0.012 below on odl.
- Tables are not written yet, so every table metric is 0 (TEDS, olmOCR `table_tests`, READoc
  `table_teds`).
- Running headers and footers are removed only by repetition across pages, which a single-page
  document cannot show: olmOCR `headers_footers` 0.356.
- READoc's holdout aggregates: best of all tools on github text similarity and reading order
  (`seg_kt` 0.993, tied with docling); below on arxiv, whose papers carry tables and formulas.

## Speed and memory

One pinned core (`--cpuset-cpus=3 --cpus=1`), the harness's 200 odl PDFs and 6 multi-page
synthetic PDFs, every document converted by a fresh process started from Python.

| tool | timing | pages/s | ms/page median | ms/page p95 | cold start s | peak RSS MiB |
|---|---|---|---|---|---|---|
| RayoPDF 0.0.1 | fresh-process | 363.6 | 2.86 | 3.93 | 0.03 | 13.5 |
| pdftotext | fresh-process | 64.3 | 17.15 | 19.83 | 0.09 | 19.1 |
| liteparse | fresh-process | 49.0 | 22.53 | 28.86 | 0.08 | 40.4 |
| edgeparse | in-process | 139.7 | 4.88 | 15.35 | 0.21 | 172.2 |

- RayoPDF's fresh-process time includes process start and about 1 ms of Python `subprocess`
  overhead. It is 6.0 times faster per page than the fastest fresh-process competitor, pdftotext.
- A throwaway in-process timer (release build, CPU 3, best of 3, odl) measured 0.75 ms/page
  median and 1.75 ms p95: 74 % in content interpretation and font loading, 26 % in lines, reading
  order, semantics and the writer, 1 % in opening the document.
- The release bar is ≤ 1 ms/page fresh-process (native timer) and ≥ 2,000 pages/s warm on one core;
  neither is reached yet.

## Known gaps

From the module reports, with the algorithms section each maps to:

- Tables (§6.7): ruled grids are recognised but written as text.
- Headers and footers of single-page documents (§5.2).
- Heading levels are renumbered from 1, so a document whose top heading is H2 loses level accuracy
  (§6.1).
- No right-to-left reordering (§4.4); white-on-white text and switched-off optional content are not
  filtered (§4.3); diacritics drawn as separate glyphs are not combined.
- Footnotes, images and math markup (§6.9); strikeout (§6.6).
- Predefined CJK CMaps without ToUnicode give no text: Adobe cmap-resources tables are not
  generated yet (§3.4).
- R5/R6 passwords are not SASLprep-normalized (§1.4).
