# RayoPDF 0.3.0 on the harness, 2026-11-14

0.3.0 adds output options for the conventions readers and benchmarks disagree on, chunks for
retrieval, a layout inspector, a C ABI with Python wheels and an npm package to the converter of
[0.2.0](v0.2.0-2026-11-13.md); it measures every benchmark both in the default output and in the
options its ground truth's conventions call for, adds the DocLayNet and OmniParseBench suites, and
landed each quality step only through a strict gate: no gated metric of any development or
validation suite more than 0.0001 below its best. Quality was measured on code `6c9b541` (core
alone unless the bundle is named; the holdouts, `readoc` and the weasyprint producer, once, on
this code); the code changes after it (a profile-guided static build tried and taken back,
`src/hot.ld` regenerated) change no byte the core writes (1,302 comparisons). Speed was measured
on the release's code. Same machine and harness as [the baselines](baselines-2026-11-05.md); the
release check is [release-check-2026-11-14](release-check-2026-11-14.md).

## New since 0.2.0

- **Output options:** `--furniture=keep` (running headers, footers and page numbers kept as text,
  before or after the page's text and never as headings), `--plain` (no inline markup) and
  `--tables=html` (every table as HTML); `--format=chunks` (JSON Lines of heading-led chunks with
  their pages and boxes, for retrieval) and `--format=inspect` (one HTML file that draws what the
  layout stages decided).
- **Embedding:** a C ABI (`include/rayopdf/rayopdf_c.h`) in a shared library, Python wheels over
  it (with LangChain and LlamaIndex loaders), and the converter built for WebAssembly as an npm
  package (browsers, Node.js 18+).
- **Declared profiles:** each benchmark declares the options its ground truth's conventions call
  for (`eval/profiles.json`: odl `--images=none --furniture=keep --plain --tables=html`, LaTeX
  math for READoc and olmOCR `arxiv_math`); records show the default row beside the declared one,
  and the strict gate measures the declared rows.
- **New suites:** DocLayNet (the roles of text cells on 6,489 development and 4,999 validation
  pages), OmniParseBench (its unit tests on 1,074 + 1,075 pages), olmOCR `arxiv_math` as its own
  suite, and two untagged producers in the synthetic corpus (chromium-untagged, context).
- **Quality, default output:** card and cover titles, chapter numbers set apart, a display
  title's stacked lines and notes at the foot of a page's columns (rules found on odl after
  0.2.0's release: odl 0.909 → 0.915, MHS 0.874 → 0.890); heading levels from clusters of the
  headings' sizes; page numbers counted up from page to page; a lone page number at the foot set
  between dashes or centred under loose text is furniture.
- **Quality, LaTeX mode:** a tagged formula's LaTeX alternate text; binomials, over- and
  undersets and horizontal braces; a script's own script drawn apart from its line.
- **Small models (M9):** `rayopdf --features` writes the vectors of two decisions the rules make,
  and a training image fits LightGBM trees on DocLayNet's train pages and on generated tables.
  Neither model met M9's criteria; none ships
  ([decision](../development/ocr_ml_decision.md#small-models-in-the-core-m9)).
- **Speed:** hex strings read in one pass, card titles tested cheaply first, a regenerated
  `hot.ld` ([performance.md](../development/performance.md#tenth-round-2026-11-13)).

## Tried and not landed

Every quality step went through the strict gate (no gated metric more than 0.0001 below its best
on any development or validation suite); a step that failed it took the plan's fallback once and
was dropped when that failed too.

- **Word gaps fitted per font** (step 2.1): the fit's own cost was +1.55 % odl instructions, its
  fallback (a fit used only from 0.18 em, every eighth glyph pair) +0.30 %. The fallback failed
  the gate on the READoc validation split's GitHub documents (`text_f1` 0.9203 → 0.9157,
  `word_sp`, `seg_sp`, `seg_kt`, `text_eds`, `word_kt` down): on a Chrome-printed page most glyph
  gaps are 0.13 em or wider, the fit fell between its word gaps and its wider gaps, and every
  word of a line joined.
- **Borderless table columns by dynamic programming** (step 2.4): a rejected run of rows tried
  again with columns chosen over its whitespace channels. It failed the gate on 24 metrics
  (READoc `table_teds` on the second development split 0.6197 → 0.6145 and on the validation split
  0.5820 → 0.5729, synthetic untagged TEDS 0.912 → 0.906); its fallback (figures in 30 % of the
  cells) failed on 24 as well (development `table_teds` 0.7232 → 0.7107).
- **Column gutters from the page's word gaps** (step 2.5): the plan's test already passed without
  it; with one text size no gutter narrower than the cut's half em reaches the splitter.
- **Stretched delimiters as `\left … \right`** (step 3.2): raised `outline_eds` on every READoc set
  (0.590 → 0.596 on the development split) and olmOCR `arxiv_math`, but lowered segment order on
  the second development and validation splits (`seg_kt` up to −0.00016, `seg_sp` −0.00023); no
  fallback stated.
- **Formula structure as a minimum-cost arborescence** (step 3.6): when the greedy rebuild gives
  up, the cheapest tree over the formula's glyphs (Eto–Suzuki edge costs, Chu–Liu/Edmonds). It
  raised olmOCR `arxiv_math` 0.7202 → 0.7205 and most READoc LaTeX keys but lowered the second
  development split's `inline_eds` by 0.00013; its fallback (only failures attaching accents in a
  row) rebuilt the same formulas and failed alike.
- **READoc table rules** (step 4.2): of the 25 second-development documents whose `table_teds`
  trails docling's by 0.1 or more, 7 are tables written as HTML (a span the pipe syntax cannot
  hold; READoc's evaluator reads only pipe tables), and every other class has fewer than the 5
  documents a rule needs. A rule for a fraction bar read as a table (4 documents) raised the
  split's `table_teds` 0.620 → 0.624 but lowered the development split's `text_eds` by 0.00005: not
  landed.
- **The edge-row furniture model** (step 5.5): raised DocLayNet `furniture_f1` (development
  0.5946 → 0.5967, validation 0.4753 → 0.4781) and olmOCR `headers_footers` 0.8486 → 0.8513, but
  lowered DocLayNet validation `heading_f1` by 0.00028
  ([M9 decision](../development/ocr_ml_decision.md#small-models-in-the-core-m9)).
- **Patent running heads as furniture** (step 4.3's second rule): DocLayNet development
  `furniture_f1` +0.0096, but one olmOCR `multi_column` test lost (a patent's gutter line numbers
  read in another order).
- **A profile-guided static build** (step 7.3): built and timed on this machine, +2.0 % warm and
  −2.0 % fresh against the plain build of the same code, with identical output; but the Release
  workflow builds on GitHub's runners, where the same three stages made a different binary, 14 %
  slower fresh (1.020 ms) and 1.4 % slower warm here than the one built here. It was taken back
  before the release, with the `hot.ld` made for it
  ([performance.md](../development/performance.md#tenth-round-2026-11-13)).
