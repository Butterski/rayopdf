# RayoPDF 0.0.5 on the harness, 2026-11-06

What changed since [0.0.4](v0.0.4-2026-11-06.md):

- **Tables:** a header label over several sub-columns becomes a `colspan` cell, with columns taken
  from the body rows; a second borderless pass accepts column gaps down to 2.5× the page's median
  word space (never under 0.6 em) for tables the 1 em pass missed; section labels inside the
  first column stay in the table; up to four number-free lines above a numeric body merge into
  one header row; wrapped first cells in shaded tables stay one row; one-column grids with
  whitespace columns are split; dot leaders removed from cells.
- **CJK:** every predefined CMap of Adobe's five collections (144, Adobe-KR added), stored as
  differences from a base CMap; CIDs without Unicode in `cid2code.txt` take the base character of
  their registered ideographic variation sequence or, in the standard Big Five and KS X 1001
  areas, the character another CID has at the same code. Unmapped Adobe-Japan1 CIDs 6,827 → 5,816.
  Surrogate pairs inside UCS-2 ToUnicode strings (emoji written by Acrobat) read as one character.
- **Right-to-left:** the bidi resolver implements UAX #9 in full (X1–X10 embeddings, overrides and
  isolates, N0 paired brackets); it passes all of UCD 16.0.0 BidiCharacterTest.txt (91,707 cases)
  and BidiTest.txt (770,241).

Same machine and harness as [the baselines](baselines-2026-11-05.md). RayoPDF ran as the harness's
`cli` tool: `build/static/rayopdf` (GCC 13.3, `-O2`, fully static, 2,255,592 bytes; +167,864 for
the CMaps and the bidi resolver), `rayopdf --convert {in} {out}` with its default image output. All
numbers are reproduced here.

- Full conversions with ASan + UBSan, images written (2,802 PDFs: synthetic, odl, olmOCR

- Five-minute fuzz runs on the final code of each module: `fuzz_layout_tables` (60,985 runs),
  `fuzz_text_cmap` (12,212), `fuzz_text_bidi` (121,947), `fuzz_text_cjk` (62,886), all clean.

## Known gaps

Those of [0.0.4](v0.0.4-2026-11-06.md#known-gaps) still open, plus:

- 5,816 Adobe-Japan1 and 1,726 Adobe-KR CIDs (proportional, italic, rotated and ruby forms) have
  no Unicode in any pinned source.
- Bracket pairs across a line break are not paired (bidi is resolved per line); a right-to-left
  run boundary can gain a space ("اليسار .").
- Identity-H fonts whose ToUnicode is unusable (28,638 unmapped codes in SafeDocs) are not
  detected or repaired.
