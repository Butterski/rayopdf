# RayoPDF 0.0.14 on the harness, 2026-11-11

0.0.14 is round 6: segment order and tables on scientific papers, and round 5's speed cost won
back (method and steps: [performance.md](../development/performance.md#sixth-round-round-5s-cost-won-back-2026-11-11)).
Same machine and harness as [the baselines](baselines-2026-11-05.md); measured on code `c09d8ef`
(core alone unless the bundle is named). On 2026-11-11 the user decided that every READoc arXiv
key is measured with `--math=latex` for the release bar (the suite's ground truth is LaTeX and its
text metric strips `$…$`; roadmap D6), and that 0.1.0 waits until every key is met. The holdouts
(`readoc`, the weasyprint producer) were measured once, on this code.

What changed in the output, each rule general and tested, each step landed through the quality
gate:

- **Notes:** a footnote's definition follows the block that references it; notes printed on the
  last page stay at the end (GFM renders both the same). Notes referenced from the title block
  (author marks) are written under it with their marks. A title block opens with a heading.
- **Text order:** amsart addresses printed after the bibliography move under the authors (when
  the author line is set in capitals); contents entries with the section number on its own line
  are no headings; an equation number set a quad after its formula is its own paragraph.
- **Tables:** e-mail addresses side by side mark an author block; more than three lines above a
  rule stack's second rule are rows when most hold numbers; sparse lattices with a full first row
  and column; two staggered rows are no table; an equation array with numbered lines is no table;
  a header label over sub-columns is repeated in each column of a pipe table (D6: row spans and
  spans below the header stay HTML); rows from vertical rules drawn row by row and tables in
  labelled sections; in LaTeX mode a number in a table cell stays text.
- **Robustness:** two slow fuzz inputs of the 0.0.13 campaign fixed with fail-closed budgets
  (ToUnicode range text, cmap inversion).

- **Segment order** now meets the bar: the holdout's `seg_kt` 0.967 → 0.981 in LaTeX mode. Most of
  it is the footnote placement (split +0.013); its cost is synthetic untagged NID and MHS −0.008
  on the three producers that print page footnotes (xelatex, xelatex-eisvogel, rayomd-tech),
  whose fixtures keep every definition at the end; they stay above every tool. The quality gate
  waived exactly those two metrics for that step (roadmap D6).
- **Tables** rose 0.528 → 0.604 on the holdout (LaTeX mode) and are the one open key. Measured
  causes on the split: READoc scores a table written as HTML 0, and writing
  every table as a pipe table would add 0.045 on the split but cost odl TEDS about 0.016 (under
  docling's 0.879) and olmOCR `table_tests` 0.010, so D6 stays; a `%` or `&` in a cell makes
  READoc's own LaTeX conversion drop the rest of the row (0.089 on the split, for every tool;
  content is never changed to avoid it); missed tables, figure text read as tables, merged rows and
  lost header rows make most of the rest.
- In LaTeX mode a number in a table cell now stays text (`308±6`, not `$308\pm6$`), as the
  ground truth writes it.
- olmOCR `table_tests` 0.623 → 0.620 (the header-label step costs three tests); the margin over
  the best text-layer tool (0.615) is thin.
- `8da6c5d` (tables beside charts, overlapping fills, close column splits; split table_teds LaTeX
  0.627 → 0.639, odl TEDS 0.8856 → 0.8865) landed while these runs converted: it is part of the
  0.0.14 commit but not of the numbers above, holdout included.

## Robustness

- Every step: release core tests (24) and the byte or quality gate; the steps that changed a
  parser of untrusted input were fuzzed for 10 minutes or more (`fuzz_layout_document`,
  `fuzz_layout_tables`, `fuzz_pdf_filters`, `fuzz_text_cjk` and `fuzz_text_program` 20 minutes
  each), clean.
- The two slow inputs of the 0.0.13 campaign: `fuzz_text_cjk` 3.8 s → 26 ms, `fuzz_text_program`
  1.7 s → under 1 ms, in the sanitizer build; minimized inputs in `tests/fuzz/regressions/`.
- Core tests pass in the ASan + UBSan, ThreadSanitizer and Windows (Wine) builds of `8da6c5d`,
  24 each, 0 warnings.
