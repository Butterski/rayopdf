# RayoPDF 0.0.3 on the harness, 2026-11-06

What changed since [0.0.2](v0.0.2-2026-11-06.md):

- **Tables:** empty sliver rows and columns between double rules dropped, one-column boxed tables,
  booktabs-style tables with mathematical content rejected, the "possible table" comment removed.
- **Headings:** more bold font names recognised (`-Medi`, `-Demi`, `CMBX`), headings ending in ":"
  or "?", captions never headings, an accent bar beside a title no longer a block quote, LaTeX
  `\section` titles at 11 pt counted as H1, display-math pieces never headings.
- **Reading order:** images act as obstacles that page-wide gaps cannot cross; justified lines are
  no longer split at their word gaps.
- **Footnotes:** a note must sit below its column's text; a raised digit after a math letter is an
  exponent, not a note marker.
- **Code listings:** line-number columns are dropped (numbered listings become one fenced block),
  a listing frame's side rules no longer make a block quote, code-heavy pages still get code
  blocks.
- **Writer:** a huge or non-finite line gap no longer overflows an integer (found by
  `fuzz_layout_tables`).
- **Harness:** a development producer `xelatex-eisvogel` (pandoc + the Eisvogel template), the
  pipeline of READoc's GitHub subset, so its layout can be studied without opening the holdout.
  The synthetic corpus now has 199 valid items; every competitor was converted and scored again
  on it.

Same machine and harness as [the baselines](baselines-2026-11-05.md). RayoPDF ran as the harness's
`cli` tool: `build/static/rayopdf` (GCC 13.3, `-O2`, fully static, 2,041,768 bytes),
`rayopdf --convert {in} {out}` with its default image output. All numbers are reproduced here.

- READoc's GitHub regression is gone. The Eisvogel producer showed its cause on development
  documents: numbered code listings in a framed box came out as quotes, inline-code fragments and
  three-column tables. Fixed in the listing rules, with no tuning on READoc.
- odl's remaining gap is tables first (TEDS 0.722 against 0.818), then headings (MHS 0.804 against
  0.822); NID is level with liteparse (0.913 against 0.914) and above docling.
- READoc arxiv `seg_kt` stays 0.022 below 0.0.1: footnotes are collected at the document's end
  (the development ground truth's convention); writing them at the end of their page restores it
  but costs synthetic NID and MHS.

## Speed and memory

One pinned core, the 200 odl PDFs and 6 multi-page synthetic PDFs, a fresh process per document
started from Python (about 1 ms of that is Python's).

| run | pages/s | ms/page median | ms/page p95 | cold start s | peak RSS MiB |
|---|---|---|---|---|---|
| 0.0.2, `--images=none` | 344.2 | 2.95 | 4.07 | 0.03 | 13.5 |
| 0.0.3, `--images=none` | 344.5 | 2.97 | 4.16 | 0.03 | 13.5 |
| 0.0.3, images written (default) | 154.0 | 3.33 | 15.71 | 0.03 | 188.2 |

In process (release, CPU 3, odl, images off) 0.0.2 and 0.0.3 measured the same, 1.02 ms/page
median, in an A/B taken while the fuzz campaign ran (0.89 ms on a quiet machine for 0.0.2).

## Robustness

- **Fuzzing, 24 h aggregate:** all 11 libFuzzer targets ran 7,857 s each with ASan and UBSan, one
  CPU per target (86,427 s in total). `fuzz_layout_tables` found a signed overflow in the writer
  after 6 minutes; its fixed build then ran its full share clean, and the input is
  `tests/fuzz/regressions/fuzz_layout_tables/writer-blank-lines-overflow`. The other ten ran clean
  on 0.0.2's code. Executions: `pdf_filters` 143.6 M, `image_decode` 19.4 M, `layout_content` 9.9
  M, `text_bidi` 9.3 M, `text_cjk` 3.1 M, `layout_tables` 2.2 M, `text_cmap` 1.1 M,
  `text_program` 1.0 M, `crypt_handler` 377 k, `pdf_document` 239 k, `layout_document` 43 k.
- Full conversions with ASan + UBSan, images written, on 0.0.2 (2,784 PDFs: synthetic, odl, olmOCR
  born-digital, SafeDocs): 0 crashes, 0 hangs, 0 sanitizer reports.

## Known gaps

Those of [0.0.2](v0.0.2-2026-11-06.md#known-gaps) still open, plus:

- Run-in headings (a bold heading that starts its paragraph's line) are not recognised.
- A wrapped listing line without its own number keeps a 3-space indent.
- odl: tables drawn as separate boxes that never touch (200), booktabs with an empty column
  (165), multi-line header cells written as several header rows (088–090).
