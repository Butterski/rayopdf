# RayoPDF 0.0.10 on the harness, 2026-11-09

What changed since [0.0.9](v0.0.9-2026-11-08.md):

- **Performance rounds 2 and 3** ([performance.md](../development/performance.md)): gray scans
  written as PNGs at their own bit depth, PNGs streamed into their files, Flate images decoded
  row by row, a faster JPEG 2000 tier-1 and 9/7 transform, embedded font programs read only when
  a shown character needs them, and many text-path steps; Markdown byte-identical at every step.
- **OCR speed:** the add-on's tiny recogniser reads every line first and small re-reads uncertain
  lines; detection stays with small ([ocr-engine.md](../development/ocr-engine.md)).
- **OCR scripts and rotation:** an optional script pack (Cyrillic, Korean, Arabic, Devanagari,
  Tamil, Kannada recognisers, half-precision) loaded only when a page needs it; pages scanned
  sideways or upside down are turned upright; legacy-encoded Indic fonts recovered word by word.
- **Second-engine cascade:** measured and not kept (no candidate came near the gate).
- **Quality:** quotes set by indentation, code marked by shading, display formulas kept whole,
  more list markers, math italics not emphasis, LaTeX margin protrusion on two-column pages;
  running heads and footers by offset baselines, off-edge titles and metadata; tables: middle-set
  cells, header rows over drawn grids, diagrams and matrices rejected.
- **Fix:** a use-after-free in nested Form XObjects with content of 15 bytes or less (present
  since 0.0.1, exposed by an inflate change of round 3), found by the ASan sweep.
- **Harness:** a `multiscript` suite (63 image-only pages in nine scripts, clean, noisy, serif,
  200 dpi and turned 90/180/270°; development only).

Same machine and harness as [the baselines](baselines-2026-11-05.md). Core alone:
`build/static/rayopdf` (3,363,080 bytes). Bundle: the release archives unpacked into one folder
(core, `rayopdf-ocr` 7,705,224 bytes, `rayopdf-ocr-models/` with small, tiny and the orientation
classifier); the script pack (21.1 MB archive) is not part of the bundle runs except
`multiscript`, where it was installed. All numbers are reproduced here.

## Robustness

- Core tests pass under ASan + UBSan, ThreadSanitizer, the Windows build (Wine) and the add-on
  configurations (`ocr`, `ocr-windows`, 22 tests each); CLI verifier 65/65; 0 warnings.
- Full conversions with ASan + UBSan, images written, core alone (2,802 PDFs): 0 sanitizer reports
  after the use-after-free fix (regression test and fuzz input added); the two largest scanned
  SafeDocs files (250 and 416 pages) exceed the sweep's 10 s cap under ASan (19 and 35 s).
- Fuzz runs of five minutes or more on every changed target, clean: `fuzz_layout_content`,
  `fuzz_layout_document` (10 min after the fix), `fuzz_layout_tables`, `fuzz_ocr_server`,
  `fuzz_common_ocr_protocol`; regression inputs replayed.

## Known gaps

- Release bar: throughput 2,000 pages/s and fresh 1 ms/page (speed), 24 h of fuzzing for the targets
  added since 0.0.3, construct F1 gates (0.951 untagged has no margin; holdout 0.836 against 0.90;
  tagged 0.928 against 0.98), `xelatex-2col` NID 0.936 (0.95), olmOCR `headers_footers` against
  docling, READoc arxiv against the best tools.
- OCR: Hebrew, Kannada and Arabic through the core (right-to-left lines turned 90/270° are not
  reordered), inline code and footnotes on OCR'd pages; peak memory of the add-on (about 0.6 GB).
- Peak memory still grows with JPEG and JPEG 2000 images (decoded whole) and with the input file.
