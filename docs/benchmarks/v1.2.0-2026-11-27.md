# RayoPDF 1.2.0 on the harness, 2026-11-27

1.2.0 is [1.1.0](v1.1.0-2026-11-26.md)'s converter that no longer drops the text of form fields
and annotations, writes more of a document in JSON (lines and words with boxes, the outline with
its pages, form fields, annotations, links, page labels, block roles), writes HTML and plain
text, reads more of a table's structure from its text, and runs on Linux arm64 and macOS with the
same output bytes as on Linux x64. Every step that changes the output went through the strict
gate (no gated metric more than its epsilon, 0.0001, below its best on any development or
validation suite); every other step was output-identical. Quality was measured on 2026-11-27 on
`0d4b42d`, whose converter is the release's (the commits after it regenerate `src/hot.ld`, output
byte-identical, and change documents), the holdouts (`readoc` and the weasyprint producer) once
and aggregate only; speed on CPU 3 against the 1.1.0 release binary, on `a745e50`. Same machine
and harness as [the baselines](baselines-2026-11-05.md); the release check is
[release-check-2026-11-27](release-check-2026-11-27.md).

## New since 1.1.0

- **Form fields and annotations:** the values of filled form fields and the text of FreeText
  annotations are drawn from their appearances and written as page text (a field without an
  appearance, or every field when the form asks for new ones, is drawn from its value and its
  default appearance); check boxes and radio buttons are task markers, `- [x]` and `- [ ]`.
  `--annotations=all|links|none` (default `all`; `links` is 1.1's output; `--no-annotations` is
  `none`). An XFA form whose fields are not read says so in a comment. SafeDocs 0000854, a form
  whose whole text is in four fields, went from 81 bytes of output to 1,825.
- **JSON** (schema 1, keys added): `--json-detail=lines|words` gives each block's lines and their
  words with boxes and text; `outline` with each entry's page; `fields` (name, type, value, page,
  box, flags); `annotations` (highlights, underlines, strike-outs, notes and FreeText, with the
  text they mark); per page its `label` and `links` (a URI or the page a GoTo link leads to); the
  document's language as `metadata.language`; a block `role` (caption, formula, page_header,
  page_footer, page_number).
- **Formats and input:** `--format=html` (one HTML5 document) and `--format=text` (plain text,
  pages separated by form feeds); chunks with `--chunk-overlap=N` and `--chunk-by=page`;
  `--convert -` and `--inspect -` read the PDF from standard input.
- **Python:** a Haystack component, `rayopdf.integrations.haystack.RayoPdfToDocument`
  (`pip install "rayopdf[haystack]"`).
- **Platforms:** Linux arm64 (the static program, the C++ library and a `manylinux_2_28_aarch64`
  wheel) and macOS on Apple silicon and Intel (program, library and wheels), built and tested on
  GitHub's runners. Every platform writes the same bytes: the code computes without fused
  multiply-adds and with a signed `char` everywhere, and its sorts give one order whatever the
  standard library (ties broken by index or by every field). The WebAssembly module, built with
  libc++, now writes the native program's output for every document of the speed steps' inputs,
  the 19 that differed before 1.2 included.
- **Tables:** a title or section row found from the text is one cell across the table in HTML and
  JSON; a first-cell line naming a section between rows is a row of its own, and one continuing the
  cell above joins it.
- **Code:** fonts named with Typewriter or Cousine, or with Mono as a word of their name, are
  monospace.
- **Speed:** a heavy page reserves its shapes and rulings, a ToUnicode stream is parsed where it
  was inflated, `--serve` copies plain text in runs and uses the batch allocator, and the
  WebAssembly module is built at -O3 with link-time optimisation
  ([performance.md](../development/performance.md#twenty-sixth-round-12)).
- **Tools:** `bench.py identical --a-opt/--b-opt`, `bench.py serve`, `bench.py hashes`; `dev.py`
  configs `arm64`, `libcxx`, `macos` and `macos-lib`; the image `rayopdf-cross:1`.

## Speed

CPU 3, the 1.1.0 release binary (SHA-256 `e3017afb…`) and 1.2.0's code (`a745e50`, static)
interleaved, 2026-11-27 19:07-19:12 UTC, nothing else running; the multi-page documents on CPUs
0-2 and 4-8:

| measure | 1.1.0 | 1.2.0 |
|---|---|---|
| odl warm, pages/s (p95 ms/page), median of three runs | 2,222 (0.704) | **2,227** (0.708), +0.2 % |
| odl fresh process, ms a document, median of 12 rotated rounds | 0.899 | **0.896**, −0.3 % paired |
| odl fresh, p95 / mean ms a document | 1.41 / 1.01 | 1.42 / **1.00** |
| odl fresh, page faults median / p95 / mean | 132 / 207 / 140 | **130** / **206** / **139** |
| odl 141 (one vector page, 4.17 MB of content), fresh | 15.1 ms, 480 faults | **14.7 ms**, **443** faults |
| 27 documents of 4 to 39 pages, sum, four workers / one | 128.9 / 188.1 ms | 130.9 / 189.9 ms |
| 40 documents of JPEG 2000 pages with their images written, warm, ms/page median | 70.3 | 70.8 (+0.4 % pages/s) |
| `--serve` over odl, 200 requests: sum / peak RSS / page faults a request | 113.8 ms / 12.3 MiB / 14.8 | **111.9 ms** / **9.9 MiB** / **11.2** |

1.1.0 measured 0.883 ms fresh and 2,228 pages/s on 2026-11-25; the same binary gave 0.899 ms and
2,222 here: the comparison is the interleaved one. 1.2.0 runs more instructions in most groups
(`--batch --workers=1`): odl +0.17 %, the synthetic corpus's six multi-page documents +0.41 %, 40
SafeDocs files +0.40 %, olmOCR's `multi_column` +0.42 %, `table_tests` +0.58 %, `arxiv_math` in
LaTeX mode +0.37 %; heavy10 −0.01 %. Most of it is the pass over every page's annotations for
form fields (odl +0.11 % when it landed) and the sorts with one order (odl +0.14 %, `table_tests`
+0.46 %). The fresh time held through fewer page faults, with `src/hot.ld` regenerated for the
new code (without it 1.2.0's code was 2.1 % slower fresh, with 137 faults at the median).

Against other tools (`tools/bench.py tools`; the other tools measured on 2026-11-09, kordoc on
2026-11-12): odl document 183, one page, 1.09 ms (1.1.0 1.07 ms in the same session); SafeDocs
0000348, 33 pages, 10.9 ms on one core (1.1.0 10.7 ms) and 7.6 ms on four (1.1.0 7.4 ms); peak RSS
2 MiB for the page, 7 MiB for the report on one core, 8 MiB on four.

## WebAssembly and footprint

The npm package's module under Node.js 22 (`bench.py wasm`, CPU 3, 2026-11-27), 1.1.0's against
1.2.0's over odl: 1,263 → 1,434 pages/s (+13.5 %), median 0.598 → 0.580 ms a page. The module's
output is the native program's on all 5,886 documents of the speed steps' inputs, images off
([release check](release-check-2026-11-27.md#output-identity)).

Footprint (the Release workflow's dry run of the release's code): the static `rayopdf` 4,536,280 B
(1.1.0: 4,343,736 B, +4.4 %: the readers of forms, annotations, outlines and page labels, the HTML
and text writers, the JSON additions), the Windows `rayopdf.exe` 5,918,368 B (5,587,414 B), the
Linux archive 2,279,247 B (2,190,176 B), the npm package 1,345,507 B (1,334,149 B); the new
platforms' programs 4,181,232 B (Linux arm64), 3,153,576 B (macOS arm64) and 3,569,920 B (macOS
x64). Every package and peak RSS per document are in the
[release check](release-check-2026-11-27.md#e-footprint).

## Tried and not landed

Quality steps, each through the strict gate with one redesign
([roadmap D6](../development/roadmap.md)):

- **Table rules R1, R3, R5, R6 and R7:** a phrase guard for boundaries crossed by words, row-group
  labels spanning their group, a header-only lattice joined with its body, a spanning first-column
  cell making the header, and header lines set to the middle. R1 and R6 moved every gated metric
  by less than 0.002 on the development suites and R7's ceiling was 0.0021 (odl TEDS, if one
  document became perfect); R3 gained OmniParseBench tables +0.0008 and lost READoc arXiv
  `table_teds` 0.00006; R5 changed no development output.
- **First versions** of the steps that landed: monospace names with TeX's typewriter fonts (14
  metrics down on READoc arXiv, LaTeX's `\texttt` read as code), title rows as one cell in the
  Markdown too (olmOCR `table_tests` one test down), section and continuation lines without the
  spacing test (READoc arXiv tables down), forms whose visible note text hid a scan's OCR layer
  (olmOCR `multi_column` −0.0023), the platforms' sorts with the first tie rules (five metrics
  down).

Speed steps tried and rejected (line building while pages are read, the output written through
`O_TMPFILE`, two smaller-memory designs) are in
[performance.md](../development/performance.md#tried-and-rejected-2026-11-26-and-27).
