# RayoPDF roadmap

RayoPDF converts PDF to Markdown and is the reverse of [RayoMD](https://github.com/Butterski/rayomd).
This document records the architecture decisions and the milestones. Every exit gate is stated
against the measured baselines in
[docs/benchmarks/baselines-2026-11-05.md](../benchmarks/baselines-2026-11-05.md), produced by the
harness that [evaluation.md](evaluation.md) specifies. The decisions cite the research notes in
`docs/research/`: [landscape](../research/landscape.md), [algorithms](../research/algorithms.md),
[OCR/ML](../research/ocr-ml.md), [small ML](../research/small-ml.md) (small learned models from
the text layer, their data and licences) and [layout math](../research/layout-math.md) (statistics
in place of fixed thresholds, formula structure).

RayoMD's decision record
([arbitrary_pdf_research_decision.md](https://github.com/Butterski/rayomd/blob/ef106cac5d8a7081cda6c02cec0f38d88048cf97/docs/development/arbitrary_pdf_research_decision.md),
"Consequences") requires a converter to be a separate package with explicit uncertainty, a
representative quality corpus, and evidence on package size, latency, RSS and security. The release
bar below turns each of those into a measured gate.

## Goal and release bar

RayoPDF 0.1.0 ships when all of the following hold on the harness of `docs/development/evaluation.md`:

- **(a) Quality.** Every quality metric is at least the best text-layer tool's. NID and MHS are also
  at least docling's local numbers. "Text-layer tools" are pdftotext, markitdown, pymupdf,
  opendataloader, liteparse and edgeparse; docling is the ML reference.
- **(b) Tables.** TEDS is at least docling's, or the table-ML branch of the M8 gate is taken.
  READoc arXiv `table_teds` is held to docling's number alone, not to (a)'s best text-layer tool
  (decided 2026-11-11, when the holdout stood at 0.602 against pymupdf's 0.685 and docling's
  0.656).
- **(c) Speed.** The fresh-process median is at most 1 ms per page on odl with one pinned core, and
  warm throughput is at least 2,000 pages/s on one core. The fresh-process figure is taken with a
  native timer (as RayoMD's `fresh.sh` does), because the harness's Python `subprocess` timing adds
  about 1 ms. Baseline for scale: the fastest warm tool is edgeparse at 139.7 pages/s, the fastest
  fresh-process tool pdftotext at 17.1 ms/page.
- **(d) Security.** Every parser entry point has a libFuzzer target with at least 24 h of clean
  aggregate fuzzing in the release campaign. An AddressSanitizer build also converts the census and
  synthetic corpora with 0 crashes and 0 hangs. Fail-closed rejections are allowed, and the
  release benchmark reports their count.
- **(e) Footprint.** The release benchmark reports binary size, package size and peak RSS per
  document.

Uncertainty is always explicit:

- A `<!-- rayopdf: … -->` comment sits at each affected spot: a page with no extractable text, a
  low-confidence table, unmapped glyphs, a repaired cross-reference table.
- `--report` emits one JSON line per document with the counters behind those comments.

## Decisions

### D1 Language and build

C++17 with CMake, mirroring RayoMD. What the build does today (`CMakeLists.txt`):

- No exceptions, RTTI, iostreams, `<filesystem>` or libm in `src/`.
- One optimisation level, `-O2`, for release builds. A per-file flag needs a measured reason
  recorded next to it; the only one is `-fno-tree-slp-vectorize` on `src/layout/lines.cpp`.
- Release builds on Linux have no unwind tables (`src/cli/no_unwind.cpp`, `src/cli/no_unwind.ld`)
  and place the code a fresh conversion runs first in the order of `src/hot.ld` (generated by
  `tools/hot_sections.py`).
- Static Linux and MinGW Windows builds.
- SIMD: x86-64's SSE2 baseline through intrinsics, chosen at compile time, each with a scalar
  reference implementation that tests compare against. Kernels for later extensions (AVX2, BMI2,
  PCLMULQDQ) are compiled with `__attribute__((target(...)))` and chosen at run time in one place,
  `src/common/cpu.h` (`CpuFeatures()`, read once); each keeps its baseline path as the reference
  the tests check it against (`ForceCpuBaseline`). Today: the inflate decode loop for BMI2
  (`src/pdf/inflate.cpp`), and the PNG writer's CRC-32 for PCLMULQDQ and Adler-32 for AVX2
  (`src/image/checksum_x86.cpp`). No hand-written assembly.

Source: [algorithms §7](../research/algorithms.md#7-speed-engineering), RayoMD
[AGENTS.md](https://github.com/Butterski/rayomd/blob/ef106cac5d8a7081cda6c02cec0f38d88048cf97/AGENTS.md)
§ Performance Guardrails.

### D2 Dependencies

- The core is our own code.
- Generated tables come from permissive sources: the Adobe Glyph List and Adobe cmap-resources
  (BSD-3-Clause), and the standard-14 font widths from pdf.js (Apache-2.0). The small models of
  M9 are generated tables too: decision trees trained by `eval/train/*.py` on DocLayNet
  (CDLA-Permissive-1.0) and RayoPDF's own generated tables, compiled into
  `src/layout/model_data.cpp` by `tools/gen_model_tables.py`; nothing is downloaded or read at run
  time.
- libdeflate (MIT) is only a test oracle, as in RayoMD; no product links it.
- Any new permissive library (MIT, BSD, Apache-2.0, zlib) needs a measured justification.
- No GPL or AGPL code in anything shipped.

Source: [algorithms §1.3, §3](../research/algorithms.md), [landscape §1](../research/landscape.md).

### D4 Pipeline

1. **Reader:** memory-mapped file, lazy cross-reference sections, repair scan.
2. **Per-page interpreter:** the content stream becomes an event list (glyph runs, rulings, fills,
   images, marked content) in a page arena.
3. **Font and Unicode resolution**, in the order of [algorithms §3.1](../research/algorithms.md#31-priority-order-spec--engines).
4. **Words and lines:** MuPDF's size-relative thresholds plus PDFBox's duplicate-glyph handling.
5. **Page layout:** XY-Cut++ geometry with Breuel's rules as the validator; headers and footers
   are removed first (rules, then the edge-row model of M9 on the rows they keep at a page's
   edge).
6. **Cross-page document semantics:** headings, lists, paragraphs continued across pages and
   columns, footnotes.
7. **Writers:** the Markdown writer and the image writer.
8. **Report:** the `--report` counters.

Pages are processed in parallel. The output must not depend on the thread count. Since 0.0.12
`--convert` reads the pages of a document on up to four threads (interpretation, lines, tables and
reading order per page; the cross-page stages on the calling thread); whatever depends on page
order is redone in order ([performance.md](performance.md#pages-in-parallel)).

Source: [algorithms §2, §4, §5, §6](../research/algorithms.md).

### D5 Source precedence

1. `rayomd-source/1` exact recovery of RayoMD-made PDFs (`--no-exact` turns it off). JSON output,
   chunks, the layout inspector and page markers need the pages' layout, so with `--format=json`,
   `--format=chunks`, `--format=inspect` or `--page-markers` a payload is not used
   (`"exact":"format"`).
2. A structure tree that passes validation.
3. The document outline.
4. Geometry heuristics.

Source: [algorithms §6.10](../research/algorithms.md#610-tagged-pdf-as-the-primary-signal),
[landscape §3](../research/landscape.md).

### D6 Output dialect

- GitHub Flavored Markdown.
- Tables are GFM pipe tables, or HTML when a body cell with text spans rows, a body cell with
  text below a header of several rows spans columns, or a cell holds several paragraphs. A label
  over several columns is repeated in each of them in a pipe table: a header label (measured
  2026-11-11: READoc-dev arXiv table TEDS +0.037, odl TEDS +0.0014, olmOCR table tests -3 of
  1020), and a body cell under a header of one row (measured 2026-11-11 on the landing code:
  READoc-dev arXiv table TEDS with `--math=latex` 0.6740 → 0.6857, default mode 0.6751 → 0.6871;
  odl TEDS 0.8967 → 0.8952; olmOCR table tests 632 → 632 of 1020, −1 with `--math=latex`;
  synthetic TEDS unchanged). A header label spanning down into the next header row stands in the
  first of them, the cell under it empty, and a cell without text needs no HTML for its span
  (decided 2026-11-11 against 0.0.15: READoc arXiv table TEDS with `--math=latex` on the
  validation split 0.5593 → 0.5744, READoc-dev 0.6860 → 0.7096; olmOCR table tests 636 of 1020
  unchanged; synthetic unchanged; odl TEDS 0.8956 → 0.8887, −0.0069, beyond the gate's tolerance,
  above docling's 0.879, and accepted). Kept as HTML after measuring: body cells spanning rows in
  the first column (arXiv +0.007, odl TEDS −0.007), every span as pipe (READoc-dev arXiv 0.7176,
  odl TEDS 0.8819, below 0.884) and every span as pipe except body cells spanning rows in a table
  of two columns (validation arXiv 0.5835, olmOCR table tests 636 → 632, odl TEDS 0.8887): that
  exception fits one odl document, not a kind of table.
- Text is escaped only where it would otherwise change the structure. `*` and `_` are escaped only
  where CommonMark could read them as emphasis delimiters: a run that can open, or could close a
  `*` or `_` written raw before it in the block, or stands beside a non-ASCII character or at the
  start of a block; so significance marks (`0.05**`, `***`) stay as they are (measured 2026-11-11:
  olmOCR table tests 632 → 636 of 1020; the HTML pandoc's CommonMark reader renders is unchanged
  on odl, synthetic, olmOCR tables and READoc-dev arXiv; under its GFM reader only three
  documents differ, each a backslash the old escape left inside a `$$` span or an autolink).
- Footnotes are `[^n]`. A note's definition follows the block that references it; notes printed
  on the last page (a one-page document's, endnotes) stay at the end. GFM renders either the same
  (decided 2026-11-11: READoc-dev arXiv `seg_kt` with `--math=latex` 0.9713 → 0.9839, `text_eds`
  +0.0075; synthetic untagged NID and MHS −0.008 on xelatex, xelatex-eisvogel and rayomd-tech,
  whose fixtures keep the definitions at the end; odl unchanged).
- Images are written as `![alt](<stem>-images/p<page>-<n>.<ext>)`: DCT streams as `.jpg`, JPX
  streams as `.jp2`, everything else decoded to `.png`.
- Math is Unicode, wrapped in `$…$` only for linear inline math. A formula's script (a raised or
  lowered glyph in a math font or a mathematical alphanumeric, Greek or math-symbol glyph, or after
  a base that is one, or after one to three italic letters of a text font) is written in Unicode
  superscript and subscript characters (`mc²`, `x₀`, `x⁽ⁱ⁾₀`) when each of its characters has one
  whose NFKC is that character; a script with a character that has none (`∂`, `→`, `×`, a
  hyphen) and raised or lowered text (`H<sub>2</sub>O`, `1<sup>st</sup>`, reference marks) are
  `<sup>`/`<sub>` (decided 2026-11-11, measured against master c68a1ee: synthetic construct F1
  sup/sub untagged 0.074/0.091 → 0.444/0.400, tagged 0.053/0.054 → 0.182/0.190, all-construct F1
  untagged 0.9507 → 0.9695, tagged 0.9283 → 0.9509, NID untagged +0.0011, tagged +0.0021; odl
  NID 0.9168 → 0.9177, TEDS 0.8952 → 0.8956, MHS 0.8397 → 0.8404; READoc-dev arXiv default mode
  `text_eds` 0.7859 → 0.8171, `table_eds` −0.0026, `table_teds` −0.0012, github unchanged; olmOCR
  pass rates unchanged; `--math=latex` output byte-identical). The rest of the synthetic misses
  are fixtures whose producer drew no script (LibreOffice, Typst and XeLaTeX drop the raw HTML
  `<sub>`/`<sup>` of c14-misc). Optional
  `--math=latex` (decided 2026-11-09) writes formulas as `$…$` / `$$…$$` LaTeX rebuilt from glyph
  geometry (an equation number after a display as `(n)`); a tagged Formula whose `/Alt` (else
  `/ActualText`) is LaTeX is written as it is instead (0.3.0), and a formula whose accents the
  greedy rebuild cannot attach is read again as a minimum-cost arborescence of its glyphs (0.3.0,
  `math_tree.h`). The default stays Unicode and its output byte-identical. For the release bar,
  the LaTeX-math metrics (olmOCR `arxiv_math`, READoc `inline_eds`) and every key of READoc arXiv
  (decided 2026-11-11: that suite's ground truth is LaTeX throughout and its text metric strips
  `$…$`) are measured with `--math=latex`, everything else in the default mode. 0.1.0 was
  released with one key open, READoc arXiv `table_teds` (decided 2026-11-11, after the key had
  been held to docling's number under (b)).
- Benchmark profiles (decided 2026-11-13). The default output is the faithful one: page
  furniture left out, emphasis, links and scripts as Markdown, tables GFM unless a span needs
  HTML, formulas as Unicode. Benchmarks' ground truths contradict each other on some of these
  conventions (odl keeps running headers and writes no inline markup and HTML tables; olmOCR's
  `headers_footers` wants furniture absent; `arxiv_math` and READoc arXiv write LaTeX), so each
  benchmark is measured with one fixed, published set of options, its declared profile in
  `eval/profiles.json`: odl `--images=none --furniture=keep --plain --tables=html --quotes=ascii`
  (quotes from 2026-11-14), olmOCR `arxiv_math` (the `olmocr-math` suite) `--math=latex`, READoc
  `--math=latex --tables=pipe` (its evaluator reads pipe tables only), the others the default.
  Version records show the default row beside the declared row where they differ; the quality
  gate measures the declared rows only, and no gated metric may fall more than 0.0001 below its
  best (AGENTS.md rule 7).
- Optional additions to the Markdown (decided 2026-11-12; off by default, the default output
  byte-identical): `--page-markers` writes `<!-- page N -->` (N the page's number in the file) as
  a block of its own before the first block of each page, and markers for pages with no block of
  their own (a page whose text only continues a paragraph, after it; pages at the end); a marker
  ends a list or block quote that runs across a page break. `--front-matter` writes YAML front
  matter first from the document information (`/Info`): `title`, `author`, `subject`,
  `keywords`, `creator`, `producer`, `created`, `modified` (only those present, each a
  double-quoted string, dates as ISO 8601 `YYYY-MM-DDTHH:MM:SS` with `Z` or `±HH:MM` when the date
  gives its offset, else as the file has them) and `pages: N`, between `---` lines and a blank
  line; not when a verified RayoMD payload that starts with its own front matter is written.
- JSON output (`--format=json`, schema 1, decided 2026-11-12): one compact JSON object and a line
  break, `{"rayopdf": VERSION, "schema": 1, "repaired": bool, "metadata": {the fields above that
  are present}, "pages": [{"page", "width", "height"}...], "blocks": [...]}`. A block has `type`
  (`heading`, `paragraph`, `list_item`, `code`, `table`, `image`, `footnote`, `comment`), `page`
  (its first page), `boxes` (`[{"page", "bbox": [x0, y0, x1, y1]}...]`: per page the union of its
  lines' boxes in points on the upright page, origin at the lower left of the crop box, two
  decimals; a turned line's box turned upright; a table's box, an image's placement; `[]` for a
  comment), then by type: heading `level`; list item `depth`, `ordered`, `number` (ordered only),
  `task` (`"open"`, `"done"`; task items only); table `rows`, `cols`, `header_rows`, `cells`
  (`[{"row", "col", "row_span", "col_span", "text"}...]`, the text a cell's inline Markdown, an
  HTML table's too; a table broken across pages is one table without the header rows its later
  parts repeat); image `file` (the link target, `null` when not written) and `alt`; footnote
  `number`; any block `quote` (its depth, when inside a quote) and `alert` (`note`, `tip`,
  `important`, `warning`, `caution`, on an alert's first block); last `markdown`, the bytes the
  Markdown output writes for the block, so that the blocks' `markdown` occur in that output in
  order. `--page-markers` and `--front-matter` have no effect on it (the metadata is always there).
- Output options for conventions on which benchmarks' ground truths contradict each other
  (decided 2026-11-13; off by default, the default output byte-identical): `--plain` writes no
  inline markup (no emphasis, code spans, strikethrough or links, whose text stays; scripts
  without `<sup>`/`<sub>` tags, Unicode script forms kept; footnote references as their number,
  definitions as `N text`; escapes and blocks as always); `--tables=html` writes every table as
  HTML, a row a line with a space between its tags and around each cell's text as HTML
  pretty-printers set them, odl's ground truth among them (2026-11-14), and `--tables=pipe` every
  table as GFM (2026-11-14; READoc's evaluator reads pipe tables only), a spanning cell's text in
  its first row and column, the cells it covers empty and header rows after the first as body
  rows (`--tables=auto`, the default: GFM unless a span needs HTML, written without the spaces);
  `--furniture=keep` removes no running header, footer, page number or margin line and writes
  them in paragraphs apart from the text, never as headings, the text read as if they were gone
  and they around it: lines turned sideways and those in a page's upper half before the page's
  text, the others after it, after the notes that end the page too (`--furniture=drop`, the
  default, removes them; a structure tree that is used still leaves out its artifacts);
  `--quotes=ascii` (2026-11-14) writes the typographic quotation marks of the pages' text
  (U+2018-U+201F) as `'` and `"`, changed in the glyphs' text once the blocks are built, so no
  stage before the writer reads them (dashes stay: ASCII has no dash apart from the hyphen, which
  dehyphenation reads; `--quotes=keep`, the default, writes them as printed). Each changes the
  JSON output's `markdown` and cells the same way.
- Chunks for retrieval (`--format=chunks`, decided 2026-11-13): JSON Lines, one compact object a
  chunk, `{"chunk": N, "heading_path": [...], "pages": [first, last], "boxes": [...], "blocks":
  [...], "markdown": "..."}`: `chunk` counts from 0; `heading_path` holds the text (without
  markup or escapes) of the headings that enclose the chunk, outermost first; `blocks` are the
  indices of its blocks in the JSON output's `blocks`, `boxes` their boxes in that order (as the
  JSON output gives them), `pages` the first and last page numbers they cover; `markdown` the
  blocks' Markdown (as the JSON output's `markdown`) joined by a blank line. Rules, in block
  order: a heading of level L ends the path's entries of level L or deeper and is pushed on it;
  it starts a chunk unless the open chunk holds only headings. A block that would take the open
  chunk's Markdown past `--chunk-chars=N` bytes (256 to 1,000,000; default 4,000) starts a new
  chunk. A block longer than N bytes alone becomes several chunks of its own, each with that one
  block and its boxes: paragraphs, list items, footnotes and headings split at the last sentence
  end within the limit (". ", "? ", "! " before an ASCII capital or digit), else at the last
  space, else at a UTF-8 character boundary; tables by rows, each piece opened with the header
  rows (GFM: the header and separator rows; HTML: `<table>` and the `<th>` rows) and an HTML
  piece closed with `</table>`; code at line ends, each piece within its fence and info string. A
  row or code line longer than N stays whole. Comments are ordinary blocks; page markers and front
  matter are not written; the repair comment is not a block and is left out.
- Layout inspector (`--format=inspect`, decided 2026-11-13; `src/layout/inspect_writer.h`): one
  deterministic HTML5 file with a `<style>` block and no script. Per page a
  `<section id="page-N">` with `<h2>Page N</h2>` and an SVG of `viewBox="0 0 W H"` in PDF points,
  drawn under `matrix(1 0 0 -1 0 H)` (origin at the lower left; text counter-flipped so it
  reads upright): every line's text as `<text>` at its start on the baseline with its
  `font-size` and `textLength` (`lengthAdjust="spacingAndGlyphs"`), turned lines along their
  direction, lines removed as running headers, footers or page numbers with class `removed`
  (grey, struck through); every block's boxes (the JSON output's) as `<rect class="t-TYPE">` with
  a `<title>` `#k TYPE [level]` and the first 120 characters of its Markdown, and its number k
  (reading order from 1, as the JSON output's blocks); one `<polyline class="order">` through the
  centres of the page's block boxes in output order; each table cell holding text as
  `<rect class="cell">` (the union of its lines' boxes); images as `<rect class="image">` with
  their file names. At most 20,000 lines are drawn a page, then a note says how many were not.
  All text is HTML-escaped (control characters as spaces, malformed UTF-8 as U+FFFD).

### D7 Command line

```
rayopdf --convert IN.pdf OUT.md [--images=DIR|none] [--password=PW] [--pages=A-B]
        [--no-exact] [--no-annotations] [--no-structure] [--math=unicode|latex]
        [--ocr=auto|off|force] [--ocr-addon=PATH] [--report] [--workers=N]
        [--format=markdown|json|chunks|inspect] [--chunk-chars=N] [--page-markers] [--front-matter]
        [--furniture=drop|keep] [--plain] [--tables=auto|html|pipe]
rayopdf --batch IN-FOLDER OUT-FOLDER [options] [--recursive] [--skip-unchanged] [--report[=FILE]]
        [--workers=N]
rayopdf --serve --json [options] [--workers=N]
rayopdf --inspect IN.pdf [--password=PW]
rayopdf --version | --help
rayopdf --bench IN.pdf TMPDIR N [options]       (developer option, performance.md)
rayopdf --features edge-rows|table-gaps IN.pdf OUT.jsonl [options]   (developer option, eval/train/)
```

`--features` converts IN.pdf on one page thread and writes, one JSON object a line, the feature
vectors of the decisions small models may learn (`src/layout/features.h`): every edge row the
furniture rules examine in the outer tenth of a page, `{"page","box":[x0,y0,x1,y1],"text","f":[16
values],"rules":0|1}` with whether the rules removed it, or every column gap of a candidate
borderless table run, `{"page","box":[x0,x1],"f":[12 values],"rules":0|1}` with whether the run
became a table. The rules' decisions are reported, not the edge-row model's (M9); the output is
that of the same conversion without `--features`.

`--no-exact` converts the pages of a RayoMD PDF that carries its source (D5 step 1,
`src/layout/exact.h`; the record's `exact` counter says whether the source was used, and why not).
One record shape serves `--report`, the batch report and the serve answers, after RayoMD's
protocol-1 record: `{"id"?, "input", "output", "status": "ok"|"skipped"|"error", "code",
"error"?, "pages", "bytes", "ms", <counters>, "markdown"? | "json"? | "chunks"? | "html"?}`, one
JSON object a line;
`code` is the exit code the document alone would give.

- **`--format=json`**, **`--format=chunks`** (with **`--chunk-chars=N`**, 256 to 1,000,000,
  else a usage error), **`--format=inspect`**, **`--page-markers`**, **`--front-matter`**,
  **`--plain`**, **`--tables=html`**, **`--tables=pipe`**, **`--furniture=keep`** and
  **`--quotes=ascii`** choose what is written (D6): the JSON document, chunks for retrieval or the
  layout inspector's HTML instead of Markdown, page markers in the Markdown, front matter before
  it, text without inline markup, every table as HTML or every table as a pipe table, page
  furniture kept, ASCII quotation marks. A RayoMD payload is not used with any of them except
  `--front-matter` (the record's `exact` is `format`).
- **`--batch`** converts the `*.pdf` files of a folder (with `--recursive` its subfolders too,
  hidden ones and links to folders excepted, mirrored) to `NAME.md` (`NAME.json` with
  `--format=json`, `NAME.jsonl` with `--format=chunks`, `NAME.html` with `--format=inspect`) and
  `NAME-images/` under the output
  folder, sorted by their UTF-8 paths. Two
  inputs with one output (`a.pdf`, `a.PDF`) leave the second refused (code 12). The exit code is
  the last failed document's, in input order.
- **`--serve --json`** answers requests `{"id"?, "input", "output"?, "args"?}` (RayoMD's protocol
  1 without its `markdown`/`source_path` input, as the input of a PDF converter is a file). The
  first line out is `{"rayopdf":"VERSION","protocol":1}`; without `output` the answer carries the
  Markdown, with `--format=json` the JSON document itself as `"json"`, with `--format=chunks`
  the chunks as one JSON array `"chunks"`, or with `--format=inspect` the HTML as the string
  `"html"`. `args` holds flags of
  `--convert` only; batch flags and unknown fields are code-2 errors and the session goes on.
  Lines are at most 1 MiB, `args` at most 64. The request reader (`src/common/serve.*`) has the
  fuzz target `fuzz_common_serve`.
- **`--workers=N`** (1–64) never changes the output. With `--batch` and `--serve` it converts
  documents in parallel, one thread each: a batch defaults to one per usable CPU, at most 6; a
  serve session to 1. With `--convert` it reads the pages of one document on N threads (default
  one per CPU, at most 4; `src/layout/convert.h`). Documents share no mutable state (the arena
  chunk pool is locked, scratch buffers are thread-local), records are written in input (request)
  order, and only `ms` varies. The converter runs clean under ThreadSanitizer
  (`tools/dev.py test --config tsan`).
- **Windows:** a static MinGW-w64 build (`tools/dev.py build --config
  windows`); paths and arguments are UTF-8 inside and UTF-16 at the Win32 API; standard streams
  are binary, so the Markdown is byte for byte the Linux build's.
- **C++ API:** `include/rayopdf/rayopdf.h` (no internal header behind it; module `src/api/`):
  `RayoPdf::Api::ConvertMemory` and `ConvertFile` with the options of `--convert` (pages,
  password, format, math, OCR, images, page markers, front matter, page threads), returning a
  `Status` whose values are the exit codes below (2 aside: options are not parsed), the error,
  the pages and the `--report` counters as one JSON object; `Version()`. The command line reads
  and opens its inputs and writes its counters through the same functions.
- **C ABI:** `include/rayopdf/rayopdf_c.h` (C99; `src/api/c/`, the object library `rayopdf_c_obj`):
  `rayopdf_convert(pdf, size, args, count, &out)` takes the flags of `--convert` as strings,
  parsed by the command line's own parser (`src/api/flags.h`), plus `--workers=N` (page threads,
  default 1) and `--images=DIR` (no images by default); it returns the exit code and fills a
  `rayopdf_output` with malloc'd, NUL-terminated `text`, `report` and `error` (empty on success),
  which `rayopdf_output_free` frees and zeroes. An unknown flag is status 2, "unknown option: X".
  `rayopdf_version()`. The language bindings call it.
- **Shared library and Python:** with `RAYOPDF_SHARED` (`tools/dev.py` configs `wheel`, in the
  manylinux_2_28 image `rayopdf-wheel:1`, and `windows`) CMake links the C ABI and every module
  into `librayopdf.so` (position-independent, hidden symbols, a version script exporting the
  three `rayopdf_*` functions, libstdc++ and libgcc linked in, no glibc symbol newer than 2.28) or
  `rayopdf.dll` (static MinGW runtime). The package `python/rayopdf` (ctypes, Python 3.9+) loads
  it from `rayopdf/_lib/`: `convert(source, **options) -> Result` (`text`, `data`, `report`,
  `pages`), `version()`, `RayoPdfError` with one subclass a status, and the loaders
  `rayopdf.integrations.langchain.RayoPdfLoader` and `rayopdf.integrations.llama_index.RayoPdfReader`
  (one document a chunk). `tests/verify_python.py` and, under Wine, `tests/c_api_smoke.c` check them.
- **WebAssembly and npm:** under Emscripten (`tools/dev.py` config `wasm`, image `rayopdf-wasm:1`)
  CMake builds the target `rayopdf_wasm` alone: `rayopdf-core.mjs` (an ES6 module factory for
  browsers and Node.js) and `rayopdf-core.wasm` from the C ABI, without threads (one page thread,
  whatever `--workers` says), without SIMD (the scalar paths) and without processes
  (`src/layout/ocr_process_none.cpp` finds no OCR add-on); no command line, batch, serve or add-on.
  `packaging/npm/rayopdf.js` wraps it: `convert(pdf, options)` with Python's option names in
  camelCase resolves to `{text, data, report, pages, images}` (images written to MEMFS `/out`,
  returned as a `Map` and deleted) or rejects with a `RayoPdfError` carrying the status;
  `version()`; types in `rayopdf.d.ts`. `tests/verify_wasm.mjs` checks it under Node.js.

### D8 Limits

The limits of [algorithms §1.5](../research/algorithms.md#15-hostile-input-limits-precedents):
object nesting 64, form XObject depth 40 with a cycle set, a page-tree cycle set, q/Q stack 256,
operand stack 64, Flate output per stream min(256 MiB, 1000 × compressed size), a per-document
decoded-bytes budget, a per-page operator budget and a per-document wall-clock budget. Every limit
fails closed and is counted in `--report`.

## Engineering conventions

Condensed from RayoMD's
[AGENTS.md](https://github.com/Butterski/rayomd/blob/ef106cac5d8a7081cda6c02cec0f38d88048cf97/AGENTS.md)
and
[docs/development/performance.md](https://github.com/Butterski/rayomd/blob/ef106cac5d8a7081cda6c02cec0f38d88048cf97/docs/development/performance.md);
those files hold the reasons.

- **Naming.** Functions and types are PascalCase (`ReadXrefSection`), constants are `kName`
  (`kMaxFormDepth`), and code lives in the `RayoPdf` namespace.
- **Errors.** Functions that can fail return a status enum (or a result struct that carries one),
  never an exception. Release builds have no exceptions, RTTI or unwind tables; never write `try`,
  `catch`, `throw`, `dynamic_cast` or `typeid`.
- **Memory.** Page work lives in per-page arenas that are reset, not freed, between pages. Nothing
  is allocated per glyph, word or line on hot paths; buffers are reused across pages and
  documents in batch and server modes. Output is written into the caller's buffer.
- **Algorithms.** Single linear scans over input; never rescan per object or per opener. Every
  expansion a hostile file can trigger draws on a document-wide budget.
- **Core tests.** One core-test runner in which every check returns its own unique exit code, so a
  failure names the check.
- **CLI verifier.** A stdlib-only Python verifier (`tests/verify_cli.py`) checks an already-built
  binary as a black box; building and timing stay outside it.
- **Fuzzing.** libFuzzer targets for every untrusted-input entry point, with a replay mode for CI.
  A minimized reproducer of every fuzz finding is committed with its fix.
- **Performance changes.** An A/A run on the same build bounds the noise; the A/B run is pinned
  (`--cpuset-cpus=3`), and the Markdown and image bytes are identical before and after unless the
  change says otherwise.
- **Records.** Measured-and-rejected ideas are written down with their date and numbers, so they
  are not tried again blindly.
